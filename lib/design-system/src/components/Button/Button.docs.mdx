## Shape and width

<Canvas of={ButtonStories.ShapeOptionsAndFullWidth} />

`shape` accepts `rounded`, `square`, or `pill`. When omitted, the button keeps the active theme's control radius. `fullWidth` makes the button fill its containing block; it defaults to `false`.

## Icons

<Canvas of={ButtonStories.IconControls} />
<Canvas of={ButtonStories.IconOnly} />

Choose an example in the **icon** select on the Icon Controls story to update all three previews. In the component API, pass an icon through `icon`; it appears on the left by default or on the right with `iconPosition="right"`. Set `iconOnly` to hide the text. Icon-only buttons require an accessible name through `aria-label` or `aria-labelledby`; icon content is treated as decorative.

## Theme boundaries and customization

<Canvas of={ButtonStories.NestedThemes} />
<Canvas of={ButtonStories.CustomThemeAndScopedOverride} />

Semantic variables are direct values, so overriding a resting action color does not alter its hover or pressed states. Register no new hook without documenting its purpose and adding it to `src/tokens/component-hooks.json`; every hook resets at nested theme boundaries.

Atom uses a more pronounced dark-to-light diagonal background gradient on filled buttons, running from the top left to the bottom right. Ghost buttons stay transparent until hovered or pressed, then use the same treatment. In forced-colors mode, the decorative gradient is removed.

## API limits

`Button` forwards native button props, refs, accessible naming attributes, `className`, and form attributes. The component deliberately does not provide `href`, `asChild`, toggle semantics, or groups.

Visual overrides are limited to the generated `DesignSystemStyle` custom-property type. Public hook names and fallback tokens are documented in the **Foundations / Customization** page.
