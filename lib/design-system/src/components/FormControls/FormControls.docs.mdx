<Title>Form controls</Title>

These theme-aware controls share accessible labels, descriptions, required states, and validation messaging. They do not manage form state or validation rules for you.

## Label

The public <a href="iframe.html?id=components-label--docs&amp;viewMode=docs">Label</a> can also be used independently. Its `required` prop adds only a visual marker; use the native `required` prop on the actual input. Its `disabled` prop styles the label but does not disable the associated control.

## TextField

<Canvas of={FormControlsStories.TextFieldStates} />

Use `TextField` for a single-line input. It forwards native input attributes such as `type`, `name`, `autoComplete`, `value`, `defaultValue`, and `onChange`. `label` is required; `description`, `error`, `required`, `disabled`, and `invalid` are optional.

Use the optional `prefix` and `suffix` slots to attach text, decorative icons, or interactive elements before or after the native input:

```tsx
<TextField label="Monthly budget" name="budget" prefix="$" suffix="USD" type="number" />
<TextField
  label="Website"
  name="website"
  prefix={<span aria-hidden="true">↗</span>}
  suffix={<Button type="button" variant="secondary">Check</Button>}
  type="url"
/>
```

Affix content remains in the accessibility tree unless the consumer marks it decorative, and interactive suffix elements keep their own native keyboard behavior and tab stop. The input retains its label, description, error, ref, and native form behavior. The group shrinks with its container; long affix text can wrap, and the input keeps the remaining available width. When the field is disabled, disable any interactive affix elements separately.

## Textarea

<Canvas of={FormControlsStories.TextareaBasics} />

`Textarea` forwards native multiline input props, including `rows`, `maxLength`, and native change handlers. It defaults to four rows and can be resized vertically.

## RangeField

Use `RangeField` to adjust a numeric value with a native slider. It supports min/max/step constraints, a visible formatted value, descriptions, errors, and disabled state. See the [RangeField documentation](iframe.html?id=components-range-field--docs&viewMode=docs) for its controlled-state and formatting API.

## Select

<Canvas of={FormControlsStories.SelectInteraction} />

`Select` renders a native `<select>` and accepts native `<option>` or `<optgroup>` children. This keeps platform keyboard navigation and form submission behavior. Its decorative chevron is positioned with the same inset as the text padding across all themes.

For long option lists where users benefit from searching, use the separate <a href="iframe.html?id=components-combobox--docs&amp;viewMode=docs">Combobox</a>. It provides a searchable, keyboard-accessible single selection while retaining the selected option's value for form submission.

## Checkbox and RadioGroup

<Canvas of={FormControlsStories.CheckboxInteraction} />
<Canvas of={FormControlsStories.RadioGroupKeyboard} />

`Checkbox` is a native checkbox. `RadioGroup` renders a native `<fieldset>` and `<legend>` with radio inputs that share the required `name`; provide the available `options` and an optional controlled `value` or `defaultValue`.

## DateField, FileField, and Switch

<Canvas of={FormControlsStories.DateFileAndSwitchInteraction} />

`DateField` wraps a native date/time input. Its `type` is limited to `date`, `datetime-local`, `month`, `time`, or `week`, and defaults to `date`; native date constraints such as `min`, `max`, and `step` remain available.

`FileField` wraps a native file input and supports browser-native `accept`, `multiple`, and file-selection behavior. File inputs cannot be controlled through `value` or `defaultValue`; use the browser's native file picker and read selected files from the input or owning form.

`Switch` is a native checkbox with switch semantics. It supports controlled and uncontrolled checked state, `name` and `value` form submission, native required validation, descriptions, errors, and disabled behavior. Space toggles the focused switch, and the visible focus indicator remains keyboard accessible.

## Organize longer forms

<Canvas of={FormControlsStories.FieldGroupingAndLayout} />

`FieldGroup` groups related controls with a native `<fieldset>` and `<legend>`. Its `disabled` prop uses native fieldset behavior, and `description`, `error`, `invalid`, and caller-provided `aria-describedby` work like the individual controls. `FormLayout` is a presentation-only grid wrapper: it stacks fields by default and can display two columns on wider screens with `columns={2}`. Set `gap` to `"sm"`, `"md"`, or `"lg"`, and use `className` for custom layout needs.

These primitives do not manage values, submission, or validation. Keep those responsibilities in the owning `<form>` and on its native controls. Native tab order, radio arrow-key behavior, required validation, and form submission remain intact.

## Validation and accessible names

Each individual control requires a visible `label`. `description` and `error` are connected to the control or group through `aria-describedby`; an error also sets `aria-invalid`. Set `invalid` when the control is invalid but has no message. Existing `aria-describedby` IDs are preserved and combined. Native `required` and `disabled` behavior is retained.

## Themes

<Canvas of={FormControlsStories.ThemeCoverage} />
<Canvas of={FormControlsStories.NestedThemeBoundaries} />

In Atom, `FieldGroup` has no drop shadow; its contained form controls retain their normal theme styling.

Controls use the active theme's semantic text, surface, border, focus, spacing, and radius tokens. ACME, Atom, Luna, and Orchid theme coverage includes date, file, and switch examples. Control boundaries, file-picker action text, disabled actions, and active switch tracks have documented contrast checks. Luna keeps single-line text and select controls pill-shaped and uses a 32px radius for both textareas and field groups. Atom uses compact, squared control corners, 8px field-group corners, thick outlines, and hard offset shadows. Error text and invalid borders use dedicated semantic roles with contrast checked across all themes.
