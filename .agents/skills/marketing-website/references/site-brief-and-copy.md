# Discovery, site brief, content strategy, and trustworthy marketing copy

Use this reference whenever the task includes new site creation, a major redesign, content planning, page structure, or conversion optimization.

## Minimum viable site brief

Copy this to the working notes or planning output and fill in only grounded information.

| Item | Required question | Safe default if unspecified |
| --- | --- | --- |
| Business | What is being offered, to whom, and where? | Describe the user's stated offering without inventing service regions |
| Audience | Who is making the purchase/contact decision? | One clear primary audience drawn from the brief |
| Need | What situation motivates the visit? | Concrete problem implied by the offering, no unverified facts |
| Outcome | What useful change will a visitor get? | Benefit written as an aspiration, not an unsupported guarantee |
| Difference | Why choose this business? | Demonstrable process or service attributes only |
| Primary action | Call, email, book, request quote, sign up? | Show a CTA; mark destination as required if unknown |
| Trust | Reviews, project images, guarantees, certifications, metrics? | Omit unverified proof; use honest process details instead |
| Asset inventory | Logo, product imagery, staff photos, icons, fonts? | Use honest neutral visuals or clearly marked placeholders |
| Pages | Home, services, about, work, FAQ, contact, legal? | Only pages with a genuine user task and content |
| Constraints | Platform, CMS, stack, hosting, languages, brand? | Keep existing project choices |
| Success | How will conversion be measured? | Define an observable event, do not invent a target rate |

Keep facts, plausible drafts, and missing owner inputs in three distinct categories. A working preview may use explicitly marked sample content, but no unapproved sample should silently become production truth.

## Default information architecture

**Home**: focused hero → primary benefit → services/product offerings → how it works → grounded differentiation → real work or proof if available → FAQ when useful → specific CTA → contact/footer.

**Service/detail**: who needs it → what is included → outcomes and boundaries → process → relevant evidence → FAQs → next step.

**About**: people/story and credentials actually supplied → operating philosophy → capability → human contact route. Don't substitute generic corporate clichés for evidence.

**Contact**: direct contact method(s), service-area details if true, minimal labeled form if configured, realistic response expectations only when known, privacy explanation where needed.

Use one page for a focused single-offering site. Separate routes only when they answer materially different visitor questions or search intents. Avoid thin, duplicated pages.

## Copy rules

- Lead with the visitor's problem and tangible outcome, not vague superlatives.
- Make headlines specific: "Weekly bookkeeping for independent contractors" is more useful than "Elevate your potential" when true.
- The supporting sentence should clarify service scope and expectations rather than merely repeat the headline.
- Name the action and result in each CTA: "Request an estimate", "View projects", "Call the shop".
- Address friction near actions: what happens after contacting, required information, how much time it takes — only when known.
- Prefer short paragraphs, descriptive headings, bullets for true lists, and balanced section lengths. Avoid walls of text or entirely meaningless one-liners.
- Do not use fabricated metrics ("98% happy clients"), fake scarcity ("only 2 spots left"), false affiliations, made-up testimonials, or stock-person biographies.
- Quote real testimonials exactly within permission and attribution constraints; do not alter substantive meaning.
- Make legal, pricing, tax, support, health, and safety claims conditional on business-owner verification or relevant professional review.

## Trust and conversion audit

The visitor should be able to identify: business identity; relevant offer; price or estimation route if applicable; service region; real contact path; next action; treatment of form data; and any meaningful limits or exclusions. Do not compensate for missing proof with invented badges.

A coherent primary CTA usually beats many competing actions. Put the action near the hero, at a relevant decision point lower on the page, and in the final section if helpful; do not make every section a giant repeated sales pitch. Test labels and routes rather than assuming a particular color or position guarantees conversions.

## Creative direction deliverable

Write 4–6 lines: **tone**, **design motif**, **typographic character**, **color roles**, **image style**, and **motion policy**. Use these to constrain all pages, so the site feels like one designed system. Prefer a small number of memorable details over ornamental overload.

## Acceptance questions

1. Can an unfamiliar visitor explain the offer and next action after scanning the first screen?
2. Does every section add useful information rather than visual filler?
3. Are claims and imagery truthful, attributed/licensed as necessary, and clearly separated from placeholders?
4. Is copy understandable without animation, hover, or images?
5. Can the actual business owner edit key content without hunting through JSX, if editability was requested?
